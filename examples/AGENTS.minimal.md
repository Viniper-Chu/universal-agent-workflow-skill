# 项目协作约定

- 按用户目标推进到可交付结果；常规选择自行判断，已明确的授权不重复询问。
- 优先沿用项目结构与工具。中间文件放既有输出目录；没有约定时放 `codex/`，只建需要的子目录。最终文件按用户要求交付。
- 保留无关改动、原始资料与用户数据。涉及删除、覆盖或迁移时先核实实际范围；软件目录和配置不能仅为整齐就搬动。
- 验证实际修改与用户使用入口。测试通过后，有新修改、失败或未决问题才扩大检查；如实说明未验证的部分。
- 沿用 Git 管理代码与需长期维护的文档，不将密钥、缓存或大型运行产物加入版本控制。“保留本次和上次”只用于已授权整理的生成物，不删除 Git 历史。
- 需要执行方法时使用 `astra-workflow`；有既定跨会话合同的任务继续遵循该合同。不要同时粘贴两套完整流程。

本文件是可选模板，放入具体项目并按实际情况调整；不自动覆盖全局或其他项目的规则。
